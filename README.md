# anki-x

在终端背英语单词，使用桌面 Anki 的真实队列、间隔重复排程和学习记录。

项目目录为 `anki-x`，启动命令为 `anki-x`；Python 包使用符合模块命名规则的 `anki_x`。当前版本 `0.2.0` 支持牌组主界面、返回导航和退出位置恢复。

## 开始学习

保持 Anki 桌面端打开，在任意终端运行：

```bash
anki-x
```

第一次启动进入牌组主界面；之后恢复上次退出时的界面。在主界面退出，下次仍回主界面；在学习页退出，下次回到对应牌组。已有的四级词库为 **英语单词::大学四级英语单词**，共 4028 张卡片。新卡数量、学习步骤和复习间隔均遵循 Anki 的牌组设置。当前账户使用 SM-2；客户端也通过相同的原生排程接口支持 Anki 配置的 FSRS，不自行计算间隔。

主界面支持完整的父子牌组层级，选中父牌组也可以直接学习它包含的卡片：

| 主界面按键 | 操作 |
| --- | --- |
| ↑ / ↓ 或 j / k | 选择牌组 |
| → / l | 展开子牌组；已展开时移动到第一个子牌组 |
| ← / h | 收起子牌组；已收起时移动到父牌组 |
| 空格 | 展开 / 收起当前牌组 |
| Enter | 进入选中的牌组学习 |
| g | 刷新牌组和学习数量 |
| a / t | 自动发音 / 顶部标题开关 |
| q / Esc | 退出并记住主界面位置 |

学习页按键：

| 按键 | 操作 |
| --- | --- |
| 空格 / Enter | 显示答案；答案已显示时不自动评分 |
| 1 | 忘记（Again） |
| 2 | 吃力，但仍然想起来（Hard） |
| 3 | 记得（Good） |
| 4 | 很轻松（Easy） |
| a | 开启 / 关闭自动发音，自动记住设置 |
| t | 显示 / 隐藏学习页顶部的 anki-x / 牌组名称，自动记住设置 |
| r | 手动重播当前词卡发音 |
| u | 撤销本次会话的上一笔评分 |
| d | 简明释义 / 词库完整释义切换 |
| j / k、↑ / ↓ | 滚动内容 |
| PageUp / PageDown | 翻页 |
| g | 从 Anki 刷新；继续检查尚未完成的操作 |
| Esc / b / Backspace | 返回牌组主界面，保留刚才的位置 |
| q | 退出；已完成的评分保存在 Anki |

先主动回忆，再翻面。忘记时选 1；2 表示回忆成功但吃力。答案页显示每个评分对应的下次复习间隔。

自动发音默认开启：每次词卡出现时播放一次，翻面和滚动不会重复播放。标题旁的 `[a 自动发音：开/关]` 显示当前状态。按 `a` 关闭时会停止正在播放的声音；再次开启会立即播放当前词卡。设置保存在 `.state/preferences.json`，下次启动沿用。更新到 `0.1.2` 后，退出旧进程再运行 `anki-x` 即可加载开关。

`0.1.3` 增加顶部标题开关：按 `t` 隐藏或显示 `anki-x / 牌组名称`，`[t 标题：开/关]` 显示当前状态。默认显示，设置会保存到 `.state/preferences.json`，下次启动沿用。单词、释义与学习进度照常显示。

界面位置保存在 `.state/navigation.json`，按 Anki 服务地址和账户分别记忆：主界面的光标、展开状态，以及学习页的卡片、正反面、详细释义和滚动位置。恢复会重新读取 Anki，不保存或复用旧评分 token。只有原卡片仍在当前可学队列且内容、排程未改变时，才恢复原阅读位置；否则继续当前可学卡片。牌组已删除时回到主界面。退出到重启之间的时间不计入答题时间。

## 其他命令

```bash
anki-x home
anki-x review --choose
anki-x review --deck "英语单词::大学四级英语单词"
anki-x decks
anki-x stats
anki-x doctor
anki-x sync
anki-x --json stats
```

`anki-x home` 强制打开主界面；`anki-x review --deck "牌组名"` 直接进入指定牌组。这两个显式入口优先于保存的退出位置。

`sync` 等待 Anki 明确完成；需要登录、选择完整同步等情况时，应在 Anki 窗口完成提示。网络等待超时后使用 `anki-x recover` 继续检查原来的操作，不重新发起同步或评分。

连接突然中断且没有拿到操作编号时，客户端保留记录并阻止再次写入。先在 Anki 核对实际结果，再运行 `anki-x recover --acknowledge` 清除未确认记录。该命令不重发、不回滚操作。

`0.1.1` 已修复学习中卡片停留后出现 `Prediction/conversion token is stale.` 的问题。评分时获取最新预测，并核对卡片和词条仍与屏幕展示一致；只有 Anki 明确在写入前拒绝的状态冲突才有限重试，网络中断或结果未知时不重发。更新代码后，按 `q` 退出并重新运行 `anki-x` 即可生效，无需重启桌面 Anki。

## 本机安装

- 命令：`~/.local/bin/anki-x`，链接到本目录的 `bin/anki-x`。
- 运行环境：Python 3.9+，仅使用标准库；macOS 发音使用系统 `afplay`。
- 桥接：官方 AnkiConnect，源码版本 `62fc13d107c2b02130e503749e9933495c6456fb`。
- 本机端点：`http://127.0.0.1:8766/api/v1`。默认 8765 已被其他程序占用，因此单独使用 8766。
- 默认牌组和地址位于本目录 `config.json`。`--url`、`ANKI_CONNECT_URL` 可以覆盖地址，`ANKI_API_KEY` 可提供已有的插件密钥。
- 运行状态位于本目录 `.state/`，不保存学习数据库。`ANKI_X_STATE_DIR` 可覆盖该目录。
- 可重新运行 `./tools/install.sh` 安装命令。移除 CLI 时只需移除 `~/.local/bin/anki-x` 链接；不会删除 Anki 卡片。

AnkiConnect 默认只监听本机。Anki 必须打开目标账户。学习时保持桌面端在牌组概览，避免同时在桌面给同一张卡片评分；状态变更会由 Anki 的 token 校验拒绝，客户端提示刷新。

已修复原四级词库模板的错误字段引用：`{{单词}}` → `{{英语单词}}`。原始模板保存在 `verification/vocabulary-template-before.json`。这没有改动词条正文或已有学习进度。

## 实现与验证

终端从 `scheduling.getQueue` 获取 Anki 当前原生队列，使用 `scheduling.predict/answer` 获取评分间隔并提交真实评分。翻面仅影响终端展示。每次评分都确认 Anki 的最终结果；撤销等待原生 undo 完成后重新读取队列，不使用缓存卡片代替数据库状态。

选择这条路径是因为本机实测发现当前 AnkiConnect 的 `reviewer.answer` GUI 通道返回内部错误，而同一临时卡通过原生 scheduling 通道评分、持久化和撤销全部成功。客户端未修改插件源代码，也不依赖这个有问题的通道。GUI reviewer 的自定义 JavaScript 排程和第三方 reviewer hooks 不属于此客户端的执行路径。

```bash
python3 -m unittest discover -s tests -v
python3 tools/smoke_navigation.py
python3 tools/smoke_anki_x.py
python3 tools/smoke_terminal.py
```

后两项需要运行中的本机 Anki。它们创建临时测试牌组，每次测试评分均撤销，随后删除测试牌组，并断言原有今日复习次数不变。覆盖四档评分、Again 再次出现、独立客户端读取持久化记录、过期 token 拒绝、原生撤销，以及真实终端中的翻面、评分、撤销、退出。

`smoke_navigation.py` 在真实 PTY 终端中运行 CLI，以隔离的牌组数据验证多次启动、树形导航、返回、界面恢复、显式入口和 Ctrl+C 保存，不接触个人 Anki 数据。

学习卡跨秒的隔离回归为 `tools/smoke_stale_prediction.py`，需安装 `anki==26.9.3` 的独立测试环境，并通过 `--addon-source` 指向官方 AnkiConnect 的插件目录。它只创建临时 collection，不连接正在学习的账户。`--tick-during-submit` 额外验证提交期间跨秒仍只写入一次评分。

中文词卡使用已有结构化字段显示单词、音标、释义和双语例句；`d` 可查看原始详细释义。其他模板转换为纯文本，图片显示占位提示；复杂 JavaScript 互动、图片遮挡和视频请继续使用桌面 Anki。已实测本机四级卡片的 MP3 播放成功。
